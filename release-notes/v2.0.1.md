## 更新

本版是 **2.0.1**，相对 `2.0.0` 是四件事：**英雄似然判定修正**、**资料包打包新增图片重编码**
（可选）、**容器部署的循环图标修复**，以及**清理冗余部署文件**。

### 英雄「最大 / 最小似然」判定修正

原来只有一条判据，而且用错了：

- **判据顺序反了**：`computeLikelihood()` 没有先比回忆卡张数，而是直接拿「轨道推进格数」排序。
  于是「卡少但推得深」的英雄会被误判成最大似然——2 张卡各推到第 3 格（共 6 格）会输给
  1 张卡推到第 10 格（10 格）。
- **格数也算错了**：数格子时把记忆节点所在的格子 `continue` 掉了，而节点固定落在第 3/7/10 格，
  所以推到第 10 格只算 7 格。

现在按两级**复合判据**排名，顺序不能颠倒：

1. **回忆卡张数**（宿命回忆 `fatedMnemos` 不算）——多者「最大似然」、少者「最小似然」；
2. 张数**相同**时才比**轨道上已推进的格数**（1–10 那排格子，节点格同样计入）；
3. 两级都**完全并列**（张数与格数都一样）的几位一起打标记——他们本来就是同一个名次，
   只给其中一位打标记会让标记随英雄排列顺序「跳人」；
4. 真·全员同分（谁都分不出高低）时都不打标记。

单张卡推进值上限按 10 格截断，避免存档里的异常值影响比较。

### 数据修正：`c5_07`「他说出了真相」

这张卡的节点位置在 hero 页与主控台两份数据里不一致（`[5,9,14]` vs `[3,7,10]`），
会让主控台的「回忆突破」提醒到第 5 格才出现、而英雄记录表第 3 格就亮灯。现已统一为 `[3,7,10]`。
全表 46 张回忆卡的节点位置现在都是第 3/7/10 格。

### 部署修复：容器里的循环图标 404

`cycle-symbols.js`（五个页面共用的循环图标注入模块）原先放在仓库根目录，而
`docker-compose.yml` 是**逐条白名单挂载**的：根目录只挂了 `index.html`、`router.php`、
`.htaccess`，所以这个文件在容器里根本不存在——主控台、地图、记录表、英雄、剧情五页的循环
图标全部静默消失，而本地直接打开页面完全看不出问题（便携版与公开镜像走整包构建，不受影响）。

现已移入 `assets/`（与 `ato-terms.js`、`campaign-session.js` 等同类模块一致，`assets/`
本来就是整目录挂载）。同时补上防护，避免同类问题再无声发生：

- `tools/test_docker_mounts.py`：新增反向检查，从页面**实际引用**的静态资源反推必须挂载的
  根级条目，逐条核对挂载覆盖（手写清单漏登记不再无声通过）；
- `tools/test_packaging_exclusions.py`：断言该文件必须随包发布，并且必须真的被 git 跟踪
  （`assets/` 是整目录忽略、再逐条白名单放行的，漏了白名单就会脱离版本控制）。

### 清理：删除冗余的 `docker-compose.nas.yml`

它与 `docker-compose.yml` 逐行重复，唯一差异是服务名 / 容器名，留着只会两边漏改。
NAS 部署直接用 `docker-compose.yml` 即可。打包排除规则仍然保留，防止它被误恢复后跟着进包。

### 资料包打包：图片重编码（可选）

`build_fan_pack.py` / `build_official_pack.py` 新增 `--image-quality`：

- 传 40–95 的质量值（常用 `85`）时，打包过程中把图片重新编码以缩小体积；
- 不传就完全不重编，保持历史行为；
- 成员名不变，透明图走调色板 PNG，**收益不够的画保持原样**；
- `--image-quality-keep` / `--image-quality-keep-file` 是豁免清单：命中的图原样进包。
  仓库带了 `asset-studio/pack-shrink-keep.txt`，把决战版图与使徒的完整面板 / Trait 大卡排除在外，
  避免重编码后细节受损；
- 重编码过的成员，清单里的 `sha256` 与大小按**新字节**记录，校验逻辑已同步。

同时修了官中覆盖图（`official-assets/`）的匹配：支持后缀不同（`CARD.png` 配 `CARD.jpg` 目标）
与按资源目录缩短一级的路径。

## 下载

Windows、macOS、Android 请下载下方对应安装包。便携版请解压到新目录，并保留旧版本的 `data/` 和本地素材
目录（图片、故事数据、`assets/bgm/` 音频都不在安装包里，需要自备）。

本版是补丁版，**存档与资料包格式都没有变化**，可以直接覆盖升级：解压到新目录后把旧目录的
`data/` 与本地素材目录搬过去即可。

Docker 镜像同步发布 `2.0.1` 标签，并把 `latest` 移到本版：

```bash
docker compose pull
docker compose up -d
```

> `v2.0.1` 这个标签此前推送过一次，但那次发布没有保留（GitHub Release 已删除），本次是重新发布，
> 标签指向新的提交。若你此前拉取过 `2.0.1` 镜像，请重新 `pull` 一次以取得本次的内容。

Android 沿用现有签名策略：未配置发布签名密钥时提供 Debug 签名 APK。不同构建的签名可能不一致，无法保证
覆盖升级；卸载会删除应用内账号、存档和素材，升级前请确认数据可恢复。

资料包为本地私有产物，不进仓库、不进安装包；仓库的 `.gitignore` 已排除 `*.atopack` 与
`official-assets/`。
