## 更新

> **这是预发布版本（rc）**，在 1.3.2-rc.1 的基础上新增 arm/v7 支持。如果你不用树莓派或 32 位 ARM 设备，功能与 1.3.2-rc.1 完全一致，无需专门升级。
>
> **Android 版注意**：本版附带的 APK 是 **Debug 签名**的。装了它，以后正式签名的版本无法覆盖升级，只能先卸载（并会丢掉应用里的账号与存档）。装之前请先看「下载」一节末尾的说明。

### Docker 镜像新增 linux/arm/v7（32 位树莓派）

- 之前公开镜像只发布了 `linux/amd64`：**32 位的 Raspberry Pi OS 拉取时会直接提示平台不匹配**（`no matching manifest for linux/arm/v7`），无论怎么配都跑不起来。现在同一个标签同时指向 `linux/amd64` 与 `linux/arm/v7`，Docker 会按本机架构自动选择，命令与 x86 服务器上完全一样，不需要加 `--platform`。树莓派 3/4/5 装 32 位系统时直接拉取即可。
- 其它架构（`linux/arm64`、`riscv64` 等）没有预构建镜像，一键安装脚本在这种情况下**不再停在 `no matching manifest`**：它会取对应版本的源码，用发布镜像的那份 `Dockerfile` 在机器上本机构建，并把 `compose.yaml` 指向本地镜像、把 `pull_policy` 改成 `never`（本地镜像不在任何 registry 里，留着 `always` 会去拉一个不存在的东西）。
  - 64 位的 Raspberry Pi OS 属于 `linux/arm64`，走的就是这条本地构建路径。想省掉自己构建，装 32 位系统用现成的 arm/v7 镜像更省事。
  - 升级方式：本地构建的镜像重跑一次安装命令即可（`docker compose pull` 对本地镜像没有意义）。
- 只做了架构层面的改动：`Dockerfile` 一行没动，基础镜像 `php:8.4-cli-alpine` 本来就有 arm32v7 清单，应用是纯静态文件加 PHP 内置服务器，两边的行为一致。arm/v7 那份镜像已由 CI 实际构建成功并推送到 GHCR；**在真机上安装运行的结果仍然需要你回报**（我这边只验证到镜像清单与构建通过，没有树莓派可跑）。

### 镜像清单已实测确认

发布后直接查询 GHCR 的 manifest，`1.3.2-rc.2` 确实是多平台索引：

~~~text
linux/amd64     sha256:6f7729147d2387ed
linux/arm/v7    sha256:cb345e0af0abe573
~~~

同一时刻对比 `1.3.1` 与 `latest`，两者仍是单架构 amd64（没有多平台索引）——也就是 issue 里报告的那个现象。预发布不覆盖 `latest`，所以要在树莓派上验证请显式指定版本。

### 1.3.2-rc.1 的内容一并包含

本版本包含 rc.1 的全部改动，此处不重复；完整清单见 [v1.3.2-rc.1 发布说明](https://github.com/banard2049-cpu/ATO_assistant/releases/tag/v1.3.2-rc.1)。要点：私有文件（`data/`、密钥、存档）不再可下载、局域网多账号不再串档案、讯飞在线语音合成在 `http://` 局域网地址下可用、资料包导入与安装的路径校验。

## 下载

Windows、macOS、Android 请下载下方对应安装包（**Android 那份是 Debug 签名，先看完本节末尾的说明再决定装不装**）。Docker 镜像同步更新（`latest` 标签不指向预发布版，用预发布版本请在安装目录的 `.env` 里写明版本号）：

~~~bash
# .env
ATO_VERSION=1.3.2-rc.2
~~~

~~~bash
docker compose pull
docker compose up -d
~~~

32 位树莓派（Raspberry Pi OS 32-bit）不需要写 `--platform`，直接按上面两条命令拉取即可拿到 arm/v7 镜像。

便携版从旧版本升级时，请解压到新目录并保留旧的 data/ 目录，登录账号和存档都在其中。**升级后请确认 `data/` 不在任何静态目录里对外暴露。**

**Android：本次附件里有 APK（`ATO-Assistant-1.3.2-rc.2.apk`），但它是 Debug 签名的。** 仓库没有配置 Android 发布签名密钥（`ANDROID_RELEASE_*` 四个 secret 缺失），构建按回退策略用了构建机自己的 Debug keystore —— CI 日志原话是 `Android release signing is not configured; using the Debug keystore. This APK must not be published.` 把代价写在这里，装之前请先看完：

- **以后配好正式签名后，正式签名的 1.3.2 无法覆盖安装这个包**：Android 只接受签名一致的包做升级，必须先卸载这个 Debug 签名版，才能装正式签名的版本。
- **卸载会连同应用数据一起删掉**：Android 端的账号与存档存在应用私有存储里（`ato-local-store`），已安装的资料包也在应用私有目录里，卸载后都找不回来。也别指望"卸载前先导出存档"：应用里的「导出状态」是浏览器 blob 下载，而 Android 端代码里没有任何下载接管（没有 `setDownloadListener`），文件落不下来。
- 所以要长期用、或者存档不能丢的话：**现在不要装这个包**，继续用 1.3.1，等配好签名密钥后的正式版 1.3.2。只想先试试 rc.2 的新东西、存档可以从头再来，那就可以装。

另外说明一句：这个 APK 不是打标签那一次构建出来的。标签 `v1.3.2-rc.2` 指向的提交里，工作流还是旧的「没配密钥就跳过 APK 构建」策略，那次 CI 只输出了一行 notice、什么都没构建；APK 是在修复该策略与一个 Android 编译错误之后，从 `main` 手动重跑发布上来的。

## 验证

- Docker 镜像：`1.3.2-rc.2` 由 CI 在 `linux/amd64` 与 `linux/arm/v7` 上实际构建并推送成功、确实是多平台索引（清单摘要见上方「镜像清单已实测确认」）；挂载不变量由 `python tools/test_docker_mounts.py` 守着（挂载点不会遮住镜像自带的程序文件、单文件挂载带 `create_host_path: false`、`pull_policy` 不是 `missing`）。
- 打包与发布规则：`python tools/test_packaging_exclusions.py`、`python tools/test_release_assets.py`、`python tools/test_android_version_code.py`、`python tools/test_android_query_parameter.py` 通过。
- APK：由 CI 的 `assembleRelease` 构建（versionCode `10302302`、versionName `1.3.2-rc.2`），构建日志明确输出使用的是 Debug keystore —— 签名状态这一条是构建日志确认的，不是推断。
- 便携版：Windows x64 / macOS x64 / macOS arm64 三个包由 CI 构建并上传，CI 只验证到打包成功这一步。
- **没有做的事**：APK 没有真机安装验证（含 Debug 签名版能否正常装、第二屏与资料包在真机上的表现），arm/v7 镜像也没有树莓派实机验证。这两项都需要你回报。
