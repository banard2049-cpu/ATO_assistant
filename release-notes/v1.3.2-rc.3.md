## 更新

> **这是预发布版本（rc）**，1.3.2 的第三个 rc。**应用功能与 1.3.2-rc.2 完全一致**，这一版改的全是发布链路本身：它是第一个由打标签的 CI 自动产出全部附件的版本（Android APK、三个便携包、多平台 Docker 镜像）。rc.2 当时是先在流水线上炸了两次、修完再手动重跑才补齐附件的。
>
> **Android 注意**：附件里的 APK 仍然是 **Debug 签名**的（仓库还没配置发布签名密钥）。装了它，以后正式签名的版本无法覆盖升级，只能先卸载，并且会一起丢掉应用里的账号与存档。只想用 rc.2 已有的功能、又不想冒丢存档的风险，继续用 1.3.1 等正式版 1.3.2 即可，详细代价见「下载」一节。

### Docker 镜像：打标签时就能自己推送多平台

- `docker-package.yml` 补上了 `docker/setup-buildx-action`。多平台构建（`linux/amd64` + `linux/arm/v7`）必须切到 `docker-container` driver，默认的 `docker` driver 只支持单平台 —— rc.2 打标签时就是在这里直接失败的（`Multi-platform build is not supported for the docker driver`），当时只能从 `main` 手动重跑补上镜像。

### Android：编译错误修好，打标签就会自动出 APK

- 修掉 `LocalSecondScreenServer` 的编译错误：局域网入口的 `allowedApiAction` 对 `java.net.URI` 调了 `getQueryParameter("action")`，而那是 `android.net.Uri` 的方法，整个 Android 工程编译不过。现在改成手写查询串解析，只依赖 JDK 的 `getRawQuery` / `URLDecoder`，并新增 `tools/test_android_query_parameter.py` 钉住放行与拒绝的边界（含键名精确匹配、重复参数取第一个、`+` 在两种解码语义下的差异）。
- 这个错误此前一直藏着：旧策略是「没配签名密钥就跳过整个 Android 构建」，工程从未真正编译过。策略已改为**回退 Debug 签名并照常构建**，所以 rc.3 起打标签就会带上 APK —— 好处是 APK 不再缺席，代价就是上面那条 Debug 签名的说明。
- 想要正式签名的包，仍然需要配好 `ANDROID_RELEASE_*` 四个仓库 secret；配好之后工作流不用改，会自动切回正式签名。

### 源码改为 MIT 许可证

- 新增根目录 `LICENSE`（MIT），README 的「许可与素材声明」相应改写：程序代码走 MIT（可自由使用、修改、分发、商用，保留版权与许可文本即可），游戏素材仍不在任何授权范围内、来源由使用者自行确保；便携版与 Docker 镜像里打包的 PHP 运行时及其扩展不适用 MIT，仍归各自许可证（PHP License 3.01 等）。

### 发布公告补齐「验证」段

- `release-notes` 的约定要求每份公告保留 更新 / 下载 / 验证 三段，`tools/test_release_assets.py` 在断言这条规则，而 rc.1 与 rc.2 的公告都漏了 `## 验证`，这条测试一直是红的（CI 里没有任何工作流跑它，所以没拦住发布）。两份公告已补齐，并且只写实际跑过的项、没跑的项目明确标注。

## 下载

Windows、macOS、Android 请下载下方对应安装包（**Android 那份是 Debug 签名，先看完本节末尾的说明再决定装不装**）。Docker 镜像同步更新（`latest` 标签不指向预发布版，用预发布版本请在安装目录的 `.env` 里写明版本号）：

~~~bash
# .env
ATO_VERSION=1.3.2-rc.3
~~~

~~~bash
docker compose pull
docker compose up -d
~~~

32 位树莓派（Raspberry Pi OS 32-bit）不需要写 `--platform`，直接按上面两条命令拉取即可拿到 arm/v7 镜像。

便携版从旧版本升级时，请解压到新目录并保留旧的 data/ 目录，登录账号和存档都在其中。**升级后请确认 `data/` 不在任何静态目录里对外暴露。**

**Android：附件里的 APK 是 Debug 签名的。** 仓库没有配置 Android 发布签名密钥（`ANDROID_RELEASE_*` 四个 secret 缺失），构建按回退策略用了构建机自己的 Debug keystore。装之前请先看完：

- **以后配好正式签名后，正式签名的版本无法覆盖安装这个包**：Android 只接受签名一致的包做升级，必须先卸载这个 Debug 签名版。
- **卸载会连同应用数据一起删掉**：Android 端的账号与存档存在应用私有存储里（`ato-local-store`），已安装的资料包也在应用私有目录里，卸载后都找不回来。也别指望"卸载前先导出存档"：应用里的「导出状态」是浏览器 blob 下载，而 Android 端代码里没有任何下载接管（没有 `setDownloadListener`），文件落不下来。
- 所以要长期用、或者存档不能丢的话：**现在不要装这个包**，继续用 1.3.1，等配好签名密钥后的正式版 1.3.2。

游戏图片、完整故事正文及 atopack 资源包由本地资料提供，不包含在公开发布附件中。

## 验证

- 打标签后由 CI 构建全部附件：Android APK（`assembleRelease`，versionName `1.3.2-rc.3`、versionCode `10302303`）、Windows x64 / macOS x64 / macOS arm64 三个便携包、以及 `linux/amd64` 与 `linux/arm/v7` 的多平台 Docker 镜像。本公告写于构建之前，实际结果以 release 附件与 Actions 记录为准。
- 发布前在本机重跑通过：`python tools/test_release_assets.py`（公告三段齐全、release 只发布安装包、不产生校验和文件）、`python tools/test_packaging_exclusions.py`、`python tools/test_docker_mounts.py`、`python tools/test_android_version_code.py`（`1.3.2-rc.3` → `10302303`，且大于 rc.2 的 `10302302`）、`python tools/test_android_query_parameter.py`（放行 5 例、拒绝 12 例）。
- 1.3.2-rc.1 那轮修复的回归同样在本机重跑通过：私有路径拦截、局域网账号隔离、接口加固（文件锁 / `expectedAccountId` / 非原子 copy 回退 / 超大请求 413）、第二屏 token 接线、讯飞在线语音合成签名、便携启动器打包排除规则。
- **没有做的事**：APK 没有真机安装验证（包括能否从 rc.2 的 Debug 签名包升级过来），arm/v7 镜像也没有树莓派实机验证；`asset-studio` 的资料包安全回归测试（`test_hostile_pack_safety.py`、`test_install_target_safety.py`）需要它自己的依赖（`python-docx` 等），本机没装、未复跑。这些都还需要你回报。
