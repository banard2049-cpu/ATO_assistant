# 探索卡资源自动结算

主控台抽出探索卡后，卡面上「只加资源」的卡会多出一个结算区块：按一下按钮，卡面写的资源就按当前外交状态直接写进记录表的资源计数器。本文说明数据是怎么来的、判定规则、以及以后怎么重新扫描。

## 为什么需要扫描

卡面的规则文字只印在图片上，程序手里没有「这张卡给什么资源」的数据。`assets/exploration-card-tags.js` 只记录了移出/连抽标签，没有资源信息。所以自动结算分两步：

1. **打标**：把 223 张探索卡（c1–c5）的规则面板逐张读出来，得到标题、每一条规则原文、以及每条规则前面那枚外交状态徽章（`Friendly+`、`Denounced-`、`Allied`、`At War` 等）。
2. **判定与扫描**：按固定规则把「获得 N 个某某资源」翻译成结构化收益，判断哪些卡是纯资源卡，并算出每张卡的基础值与条件分支。

## 数据流水线

| 文件 | 作用 |
|---|---|
| `assets/exploration-cards/<cycle>/<id>.png` | 卡面原图（发布包自带） |
| 打标批次 JSON（视觉转录，按批存放） | **输入**：逐张卡的转录结果（标题、规则行、行首徽章） |
| `tools/merge_exploration_vision.py` | 把批次 JSON 合并成一份完整转录 |
| `tools/exploration-card-effects.json` | **输入**：合并后的逐张卡转录（已入库，扫描脚本的输入） |
| `record/index.html` | **输入**：记录表的资源表（每个循环有哪些资源、哪些资源跨循环共用） |
| `tools/scan_exploration_resource_cards.py` | 扫描脚本：判定 + 扫描 + 生成 |
| `tools/exploration-card-resources-review.csv` | 复核表：每张卡的判定、基础值、条件分支、待办效果、未识别项 |
| `assets/exploration-card-resources.js` | **运行时数据**：程序真正读取的卡数据（脚本生成，不要手改） |
| `assets/exploration-card-resource-rules.js` | 运行时逻辑：条件求值、结算计划、写记录表 / 撤销 |
| `assets/exploration-card-effects.js` | 已核实图标、记录表计数与主控台轨道变更 / 撤销 |
| `assets/exploration-card-conditions.js` | 已核实图标与数值条件、C1 陌生人动态判定 |
| `assets/exploration-card-options.js` | 五个循环的商人兑换、String Wish 持续标记与撤销 |
| `assets/exploration-card-delays.js` | 延迟队列、临时科技禁用及定时战斗触发 |

重新扫描（改了卡面转录或记录表资源表之后）：

```bash
# 只有重新打标之后才需要这一步：把批次转录合并成一份
python tools/merge_exploration_vision.py --input tools/vision-batches

# 判定 + 扫描 + 生成运行时数据
python tools/scan_exploration_resource_cards.py
```

两个脚本都不做网络请求。视觉打标是人工复核过的步骤，脚本只处理它的结果，不重新识字。

2026-10-18 全卡面复核后，已将此前只存在于运行时文件的 27 张卡修正同步回转录输入。以后修正应写入 `lines`（原文与徽章），必要时用卡级 `diplomacyFaction`、行级 `conditionLabel` 保留指定阵营和说明，再运行扫描脚本；不要直接修改生成文件。括号内的故事书页码会保留在同一句中。

移出与连抽是两个独立标签：例如 C1 #8201 Theseus's Cache 暂时移出，但不继续抽当前堆。运行时、主页面回退逻辑、五循环打标编辑器与保存接口均保留显式的 `draw: "single"`；只有未提供 `draw` 的旧标签才沿用移出后连抽的默认值。

## 判定规则

扫描脚本对每张卡逐句判断，句子来源是转录里的规则行（按句号切分，移出牌堆的说明句直接忽略，它有独立的标签系统管着）：

- **收益句**：匹配 `Gain <数量> <资源名> resources` 的句子记为该卡的资源收益，数量支持「Gain 9 Trireme, 6 Monument and 3 Armament resources」这种一行多资源。
- **条件分支**：句首带徽章就是条件收益；句子里出现 `instead` 的是「替换」分支（会顶掉它前面同资源的基础收益），没有 `instead` 的是「追加」收益。
- **其它效果**：剩下读得通的句子进 `manual`，带上它自己的徽章；`You may ...` 这类需要玩家选择的句子一定进 `manual`，不会自动加。

卡的种类（`kind`）：

| kind | 含义 | 界面行为 |
|---|---|---|
| `resource-only` | 整张卡的效果就是获得资源（可以带 `instead` 条件分支） | 显示「自动结算」 |
| `resource-plus` | 除资源外还有别的效果（选定的阿尔戈英雄 +1、失去泰坦、战斗、掷骰…） | 显示「结算资源部分」，并把其余效果列成待办 |
| `none` | 没有可识别的资源收益 | 仍显示完整效果清单与未识别资源提示 |

### 条件徽章

资源卡上的条件就是外交状态徽章，判定使用相关阵营的 `diplomacyStatus` 的 `bonus`。卡面明确指定阵营时，读取该阵营的外交记录（运行时数据的 `diplomacyFaction`）；否则读取当前地图板块的本地阵营。板块有多个本地阵营时，先由玩家选择本次适用的一个阵营，资源与其它效果都只按该阵营判定（规则书 P15、P23）。指定阵营的卡及其阵营 ID 保存在扫描脚本的 `NAMED_DIPLOMACY_FACTIONS` 中，重新生成数据时会保留。

| 徽章 | 生效条件 |
|---|---|
| `Allied` | bonus ≥ +2（结盟或更好） |
| `Friendly+` | bonus ≥ +1（友善或更好） |
| `Friendly` / `Neutral` / `Unfriendly` / `Denounced` | 恰好等于该状态（只在多分支的外交卡上出现） |
| `Denounced-` | bonus ≤ −2（恶劣或更差） |
| `At War` | bonus ≤ −3（开战） |

拿不到适用阵营的外交记录（板块没阵营、或记录表里还没填该阵营的外交值）时，按钮会给出可结算的条件分支，让玩家按实际战况选择；不会使用另一个阵营的关系来替代。

## 运行时行为

- 抽牌或重新读取记录表后，按当前关系与条件只剩一项、完全识别且无需选择的数值效果自动写入，例如泰坦 +1、巴比伦债务 +1。牌面显示「已自动结算」并可撤销；当前牌组已无待办时按钮改为「结算完毕」。含其他效果、未知条件、资源选项或泰坦损失选择的卡仍走原结算流程。撤销后本轮暂停该项自动执行，再次主动结算仍可应用。自动写入与一键结算共用服务端回执，重复操作不重复加值。
- C1 #6403 友善行提供钙化指节骨与血肉块两个不同选项，选择时连同陌生人 +1 在同一笔保存中结算。扫描器保留资源句后的附带效果，并在旧效果列表末尾追加以保持原回执编号。撤销资源结算同时撤销实际附带收益；当前抽牌已有资源回执但漏记陌生人的，会在重新读取记录后补记一次。
- 主按钮改为「一键结算」：以最新记录表在一笔保存中依次处理当前两堆中条件确定的资源、船员、命运、陌生人、新增梦行者、无需选择的泰坦损失、已有 String Wish 的已知分支还款与延迟安排。资源有未决替换分支时整项保留选择，不抢先发放基础值。
- 结算后展示自动处理项数与全部剩余待办；有待办时按钮改为「结算完毕」。点击即确认剩余效果已手动处理，按最新记录表结算追踪并结束本轮，不要求逐项标记或再次确认，也不重复执行卡牌的自动效果；全部处理后自动结束。外交卡只处理适用关系那行，多个本地阵营、缺少外交记录或首次 String Wish 仍需先选择。
- 五个循环都常驻显示「选择探索卡库」与「暂时移出牌堆」入口，空牌堆显示说明，切换循环不会因空牌堆隐藏卡库入口。
- 每次抽牌按循环、卡号和抽牌时间保存服务端 `record.explorationBatchReceipts`。单卡结算、撤销与批量处理共用回执；重复点击、保存应答丢失后重试及版本冲突重试均不会重复增加资源。已有服务端回执的删除同样为权威，避免撤销标记被旧本地存档恢复。写入后切换档案或循环时不回填新档案的完成状态。
- 按钮只出现在本次抽出的牌上（下方「暂时移出牌堆」折叠区里的牌不带按钮，避免误结算）。
- 点「自动结算」后：算出资源变更 → 通过 `api/campaign-state.php` 的 `section=record` 写入当前活动档案的记录表（读改写 + `expectedRevision` 冲突重试），并往记录表的同步日志里写一行。
- 写入的字段跟记录表页面一致：跨循环共用资源用原 key（`fearEssence`），单循环资源带循环前缀（`c1-trireme`）；稀有资源写进记录表的文本框（第二件记为 `名称 ×2`）。这份映射由扫描脚本从 `record/index.html` 的 `cycleData` 里读出来，不要手写第二份。
- 结算过的卡会记住（存进主控台 `state.exploration.settledByCycle`，按循环 + 卡 + 天数），显示「已结算 + 资源清单」并提供「撤销结算」；撤销走同一条写入通道做减法，把记录表还原。
- 下一次「抽探索卡」会清掉上一轮的已结算标记，同一天重复抽到同一张卡仍可结算。
- 只读窗口（未接管编辑）里按钮被 CSS 禁用，不会写存档。
- C4 `9326` 的整堆限制会拦截同堆所有正资源收益、祭司与新增泰坦；另一堆及其他效果照常处理。
- 资源结算后继续保留附加效果。船员、阿尔戈号命运与泰坦的明确增减可写入记录表；「结算记录表效果」一次处理已确定条件且不需选择泰坦的效果，使用同一笔记录表保存。
- 新增泰坦每只创建一条「梦行者」记录。失去泰坦需先选对象，只扣对应数量，不自动增加死亡计数。船员沿用循环上限与 C2 的船员／难民／俘虏计数；命运按循环保存。撤销使用实际变更量，保留其他字段的后续修改。
- 未知图标或外交条件必须由玩家确认；含 `if/or/unless` 的复杂规则仍保留为手动效果。已处理项可标记完成或恢复待办；点击「结算完毕」可直接确认已手动处理，其他结束入口仍提示尚未处理的资源与效果，取消会保留当前牌堆。
- 效果完成状态保存于 `state.exploration.effectStateByCycle`，下一轮抽牌时重置。每张卡首次处理后保留本次适用外交上下文，避免资源写入后刷新造成待办分支变化。
- 十二张多行外交卡只显示当前关系对应的效果行，说明句与其他关系行不作为待办；独立数值条件继续按最新记录判定。未录入指定阵营外交时先选择本次关系。C5「Aligned with Nemesis」按最差外交级别 `bonus ≤ −3` 判定。扫描时完整保留 `ICON(...)` 的内容及其条件，不将图标描述中的 `resource` 误当成资源句。
- 已核实的普通数值增减支持船员、命运、陌生人、泰坦、人性、叛逃者、悖论、冻结时间、巴比伦债务、偏执、祭司、进展、毁灭及知识。C4 Waster Caravan 按实际关系行区分进展、命运、债务与毁灭，友善行的 Mnemos 仍需玩家分配。C2 人形门槛读取叛逃者，C3 角形门槛读取悖论，C5 手形门槛读取偏执。
- 船体普通增减也支持写表与撤销，沿用各循环的船体上限和 C2/C3 最大值锁定。C3 #13519 的结盟行扣命运 1，C4 #9300 的开战行扣船体 1，C4 #9337 的恶劣或更差行加巴比伦债务 2；重复的模糊图标转录按具体卡号核实，避免将命运、船体、灾祸或猜忌混为同一计数。
- 进展、毁灭与知识同时写入主控台的对应轨道，以记录表事务和已处理编号同步；保存应答丢失后重试或撤销不会重复移动轨道，后续手动改值仍保留。已人工完成的整行不会因新增图标支持而重复执行。旧版误将命运损失转录为泰坦损失的六张卡，以及新识别的旧部分结算，会提示撤销旧结算后重算。
- 已核实的 C1 命运／陌生人图标及 C4 命运／巴比伦债务门槛自动判定；缺失数值与尚未核实的图标保留人工确认。C1 坏日子在写入时按最新陌生人、船员和命运重算，先处理损失，再处理没有失去船员的收益与命运加成。缺少任一必需数值时保留整项待办，不先发放命运奖励；整项手动完成后即使补齐数值也不会自动重算。旧版部分结算保留撤销入口，避免升级后重复发奖。
- 商人兑换选项与倍率次数由玩家选择；程序检查整笔成本、同时扣增资源、保存每轮最多五类兑换的限制，并可撤销。同一种兑换填写任意倍率仍只占 1 类，五类用满后仍可继续给已用过的类别加量。图标额外收益仍单独列出。String Wish 保存所选资源与五次还款标记，后续自动读取门槛扣费，无法支付整笔时增加 1 巴比伦债务并减 1 标记；撤销只允许当前最新标记状态。
- 商人兑换项目及当前选项说明在两边标注实际库存（如「3 船材（库存 9） → 1 石筑（库存 0）」），兑换或撤销后刷新，保留所选方案。C1 Friendly+ 的自选资源奖励提供独立选择与领取入口；按适用外交条件显示，读取最新记录复核，单次领取不占五类兑换限额，可撤销且不会重复领取。旧版手动完成标记仍保留。
- 明确且满足条件的延迟效果自动登记。山门先确认已解锁的 AA 候选，随机禁用一项；D+10 或之后进入同循环发展步骤时自动恢复，并在科技页显示临时禁用和修复日。科技解锁及前置关系保持原样。
- 探索结束后战斗转为待处理入口；战斗本身由玩家完成（今日战斗由遭遇步骤的提醒指路故事书战斗模块）。遭遇步骤**不再**放「开始定时战斗 / 定时战斗已完成」按钮：勾选遭遇步骤即视为当天的定时战斗结束，此时结算「下次定时战斗开始时…」与「…结束时…」的延迟效果，并放回暂时移出的探索卡。事件编号按「循环 + 日期」取值，同一天重复勾选不会重复结算。一次性期限会在这时重置；地图指示物到期目前提供待办，不自动改动地图。

## 已知限制

- **需要玩家选择**：商人方案、兑换类别与倍率次数、首次 String Wish 资源、资源二选一及多个候选泰坦的损失对象。选择后的商人、String Wish 与泰坦损失已有写表入口。
- **尚未接入效果执行**：英雄 A / Mnemos 分配、绝望 / 诅咒 / 恐惧、地图移动和标记、计数的复杂计算或选择、装备 / 祭司卡池 / 神形的复杂操作、掷骰 / 检定 / 故事 / 战斗本体。延迟触发和次数限制可以登记，实际事件及未知收益仍需处理。
- **图标条件**：少数卡的条件是纯图形徽章（时间线/毁灭计数一类，如 `ICON(...)/5+`），没有文字可读，扫描结果标成 `icon` 条件，结算时归到「让玩家点选分支」。
- **未知图标**：已核实图标可以执行；少数含糊转录或不能确定身份的图标仍保留手动处理。未识别收益带原始外交或数值条件，仅显示适用的那一行。
- **转录误差**：数字与徽章来自视觉打标，`tools/exploration-card-resources-review.csv` 保留了每张卡的原始句子与备注，发现不一致时改转录文件再跑一次脚本即可。
- c3 的卡名在主控台牌库里仍是「Cycle III 探索卡 <id>」；扫描数据里有真实标题（`titleZh`/`titleEn`），牌库改名不在本次改动范围内。
